# 0001. 방 큐를 Redis Sorted Set에 둔다

- 날짜: 2026-10-09
- 상태: 채택됨

## 상황

방의 큐는 곡 추가·투표·스킵이 초 단위로 일어나고, 변경 즉시 방 전원에게 브로드캐스트해야 한다. 방은 6시간 뒤 사라지므로 큐 자체는 영속 데이터가 아니다. 재생이 끝난 곡만 `PlayHistory`로 DB에 남기면 된다.

## 선택지

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| A. PostgreSQL 테이블 (`queue_item` + `vote`) | 트랜잭션, 익숙함 | 투표마다 UPDATE + ORDER BY 재조회, 방 만료 시 삭제 배치 필요 |
| B. Redis Sorted Set (score = 투표·시각 합성) | ZADD 한 번에 정렬 끝, TTL로 자동 만료, Pub/Sub와 같은 저장소 | 트랜잭션 없음 → 동시성은 락/Lua로 직접 처리 |
| C. 서버 메모리 (`ConcurrentHashMap`) | 가장 빠름 | 서버 재시작 시 소실, 서버 2대면 불일치 |

## 결정

**B를 선택한다.** 큐는 "자주 바뀌고 수명이 짧은 상태"라 Redis의 성격과 맞고, 정렬·만료·브로드캐스트를 한 저장소에서 해결한다. 동시성은 ADR 0002에서 다룬다.

## 결과

- 큐 관련 코드는 `RoomQueueRedisRepository` 한 곳에만 Redis 명령을 둔다.
- score 계산식 `votes × 10¹² − addedAtMs` 은 `QueueScore` 유틸로 고정한다.
- 재검토 신호: 큐 이력을 분석(통계·추천)에 써야 하는 요구가 생기면 DB 복제가 필요하다.
